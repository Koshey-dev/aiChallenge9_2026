# aiChallenge — эксперименты с LLM по чистому REST

Учебный проект курса по ИИ-агентам.

- `main.py` — чат с моделью: вопрос уходит в LLM по REST, ответ приходит потоком.
- `compare.py` — один и тот же вопрос на пяти уровнях контроля ответа: формат,
  длина, условие завершения.
- `web/` — веб-стенд из двух страниц: одна задача на четырёх способах рассуждения
  с четырьмя потоками ответов сразу, и та же задача на трёх температурах по пять
  прогонов с замером разнообразия.

Консольная часть сделана без SDK и фреймворков — голые HTTP-запросы через
`requests`, чтобы было видно, что именно уходит на сервер и что приходит обратно.
Веб-стенду понадобился сервер, поэтому там FastAPI, но запросы к модели остались
такими же ручными.

## Что умеет чат

- Диалог в консоли с сохранением истории: модель помнит предыдущие реплики
- Потоковый вывод ответа по мере генерации (Server-Sent Events)
- Работает с любым OpenAI-совместимым провайдером — меняются две константы

## Требования

- Python 3.10 или новее
- Ключ Google AI Studio: https://aistudio.google.com/apikey (бесплатный тариф, карта не нужна)

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env
```

Открыть `.env` и вписать ключ:

```
GEMINI_API_KEY=ваш_ключ
```

`.env` в `.gitignore` — ключ в репозиторий не попадёт.

## Запуск

```bash
py main.py
```

На Windows запускать через `py`, а не `python`: если в `PATH` есть другой
интерпретатор (например из MSYS2), он перехватит вызов и не найдёт
установленные пакеты.

Пример сессии:

```
╔═══════════════════════════════════════╗
║  ЧАТ С МОДЕЛЬЮ GEMINI-3.5-FLASH-LITE  ║
╚═══════════════════════════════════════╝
Запросы идут по REST API: POST https://generativelanguage.googleapis.com/...
Пустая строка или exit — выход.

> А население?

```

## Как устроено

Запрос уходит на OpenAI-совместимый эндпоинт Gemini:

```
POST https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
Authorization: Bearer <ключ>
```

Тело — модель, вся история диалога и флаг потоковой отдачи:

```json
{
  "model": "gemini-3.5-flash-lite",
  "messages": [{"role": "user", "content": "..."}],
  "stream": true
}
```

Ключевые моменты реализации:

- **История.** Список `messages` живёт между итерациями цикла, ответ модели
  дописывается в него с ролью `assistant`. Без этого каждый вопрос уходил бы
  в пустоту, и «а население?» осталось бы без ответа.
- **Стриминг.** `stream=True` в `requests.post` не даёт библиотеке ждать
  ответ целиком, `flush=True` в `print` выталкивает символы в терминал сразу.
- **Кодировка SSE.** Строки режутся по байтам и декодируются в UTF-8 вручную.
  Штатный `iter_lines(decode_unicode=True)` здесь не годится: заголовок
  `text/event-stream` не несёт charset, requests откатывается на ISO-8859-1,
  и кириллица превращается в мусор, а JSON рвётся посреди символа.

## Сравнение уровней контроля ответа

```bash
py compare.py
```

Один и тот же вопрос уходит пятью запросами. Перед каждым печатаются параметры
запроса, после ответа — счётчики и `finish_reason`. Между уровнями пауза на Enter.

| Уровень | Чем ограничен | Что видно в ответе |
|---------|---------------|--------------------|
| L0 | ничем | простыня на 3000+ символов с заголовками и примерами |
| L1 | `max_tokens: 60` | обрыв на полуслове, `finish_reason: length` |
| L2 | инструкция в промпте | три пункта как просили, но `###КОНЕЦ` остался в тексте |
| L3 | промпт плюс `max_tokens` и `stop` | то же, но стоп-слово срезал сервер |
| L4 | `response_format: json_schema` | готовый JSON, парсится без чистки |

Главное в паре L2/L3. Ответы почти одинаковые, но инструкция в промпте — это
просьба: модель её выполнила и честно дописала стоп-слово в текст. Параметры
`max_tokens` и `stop` выполняет сервер, независимо от того, что решила модель, —
поэтому в L3 генерация оборвалась на совпадении и `###КОНЕЦ` в ответ не попал.

Ответы недетерминированы даже при `temperature: 0.2`: формулировки и счётчики
от прогона к прогону меняются.

## Веб-стенд: четыре способа рассуждения

```bash
py -m uvicorn app:app --app-dir web --port 8000
```

Открыть `http://127.0.0.1:8000`. Задача пишется в поле — своя или выбранная из
списка готовых, — дальше кнопка «Запустить всё» отправляет четыре запроса разом,
и панели наливаются текстом одновременно. Кнопки отдельных способов перезапускают
любой из них по одному.

Обе страницы стенда поднимает одна команда, ссылки между ними стоят в шапке. На
первой странице переход сделан ссылкой, а не кнопкой, намеренно: на время прогона
скрипт выключает все кнопки, а уйти на вторую страницу может понадобиться как раз
посреди двухминутного прогона.

| Способ | Что делает | Запросов к API |
|--------|------------|----------------|
| 1 — прямой | только задача, никаких инструкций | 1 |
| 2 — пошагово | в промпте требование рассуждать по шагам | 1 |
| 3 — свой промпт | модель пишет промпт себе, потом решает по нему | 2 |
| 4 — эксперты | инструкции трём ролям, роли параллельно, решала сводит | 5 |

Третий способ показывает в панели тот промпт, который модель сочинила себе, —
без этого он визуально неотличим от первого. Четвёртый разворачивается в три
колонки по ролям (аналитик, инженер, критик) и блок решалы под ними. Роли не
видят ответов друг друга, поэтому критик разбирает не чужие решения, а саму
задачу: ищет двусмысленности и крайние случаи. В сводку от четвёртого способа
идёт ответ решалы.

Под сводкой две части, помеченные отдельно: таблица измеренного — время, символы,
токены, число запросов, стоимость — и абзац с вердиктом модели. Первому можно
верить, второй модель пишет сама про себя.

Ключ можно вставить свой: поле в шапке, по умолчанию пустое. Введённый ключ
никуда не сохраняется и живёт только в памяти обработчика запроса.

Ответы показываются с разметкой: жирный, курсив, заголовки, списки и блоки кода
разбираются на лету, по мере прихода текста. HTML из ответа модели экранируется
до разбора, поэтому подсунуть разметку через ответ нельзя. Формулы вида `$O(N)$`
остаются как есть — это LaTeX, для него нужна отдельная библиотека.

Две находки по дороге:

- **Токены в потоке.** С `stream_options: {"include_usage": true}` объект `usage`
  приходит в каждом чанке нарастающим итогом, а не один раз в конце. Складывать
  их нельзя — счётчик раздувается примерно в двадцать раз; берётся последнее
  значение за запрос.
- **Гео-блокировка.** Gemini отвечает `400 User location is not supported`, если
  запрос ушёл из закрытой страны, и ключ посетителя тут не помогает — проверяется
  адрес отправителя. Лечится переменной `LLM_PROXY`: задана — запросы к модели
  идут через SOCKS-прокси, не задана — напрямую.

## Температура: три значения, пять прогонов

Вторая страница стенда — `/temperature`. Один и тот же запрос уходит на трёх
температурах (`0`, `0.7`, `1.2`) по пять раз, ответы ложатся в три колонки. Задач
две, обе редактируются: закрытая фактическая и открытая творческая.

Над каждой колонкой два числа — сколько уникальных ответов из пяти и средняя
попарная схожесть текстов (`difflib`, без внешних библиотек). Под каждым ответом
кнопка «этот лучше»: отметок сколько угодно, счётчик над колонкой показывает, куда
попал выбор человека. Голоса живут в странице и пропадают при обновлении вместе с
ответами.

Тридцать запросов на обе задачи плюс два вердикта модели. Бесплатный тариф даёт
**15 запросов в минуту на модель** — это видно из ответа `429` с текстом
`GenerateRequestsPerMinutePerProjectPerModel-FreeTier, quotaValue: 15`, — поэтому
старт запроса разрешён не чаще одного раза в 4,2 секунды. Отсчёт общий для обеих
задач: с отдельным на каждую задачу лимит трещал ровно на стыке. Полный прогон —
около двух с половиной минут, тридцать два запроса, меньше трёх десятых цента.

### Что показал замер

Ожидаемая картина «выше температура — больше разнообразия» не подтвердилась ни в
одном из трёх прогонов.

| Уникальных ответов из 5 | `0` | `0.7` | `1.2` |
|-------------------------|-----|-------|-------|
| закрытый вопрос         | 2   | 2     | 1–2   |
| открытая задача         | 5   | 4–5   | 4     |

Разброс определяет тип задачи, а не температура: открытый вопрос даёт разные
ответы даже на нуле, закрытый — почти одинаковые даже на 1.2. Сам факт при этом не
поплыл ни разу, `1965` во всех ответах.

Параметр до модели доходит и по дороге не теряется: значение вне диапазона сервер
отклоняет с `temperature must be in the range [0.0, 2.0]`. Проверить это стоило до
того, как писать выводы про слабый эффект, — иначе вывод был бы про сломанный код.

Точность машиной не меряется: у творческой задачи нет правильного ответа, а у
фактической ответ верен на всех температурах. Её оценивает человек кнопкой
«этот лучше».

### Как развёрнут стенд

Ubuntu 24.04 на капсуле. Caddy получает сертификат Let's Encrypt на имя вида
`<ip>.nip.io` — домен покупать не пришлось, — спрашивает пароль и проксирует на
uvicorn, поднятый systemd-службой. Запросы к модели уходят через локальный
SOCKS-прокси, поднятый отдельной службой; маршрут по умолчанию не трогали,
поэтому весь остальной трафик сервера идёт напрямую.

## Смена провайдера

Эндпоинт OpenAI-совместимый, поэтому переезд — это правка `URL` и `MODEL`
в нужном файле (`main.py`, `compare.py` или `web/app.py`), заголовок
`Authorization: Bearer` везде одинаковый:

| Провайдер  | URL                                                |
|------------|----------------------------------------------------|
| Gemini     | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` |
| Groq       | `https://api.groq.com/openai/v1/chat/completions`  |
| DeepSeek   | `https://api.deepseek.com/v1/chat/completions`     |
| OpenRouter | `https://openrouter.ai/api/v1/chat/completions`    |

## Ограничения

Ни чат, ни стенд не агент:

- Нет инструментов. Модель не может прочитать файл, выполнить команду или
  узнать текущее время — только сгенерировать текст.
- История диалога в `main.py` живёт в памяти процесса. Закрыл — забыл.
- Стенд не хранит ничего: ответы, метрики и отметки «этот лучше» пропадают при
  обновлении страницы.
- Ответ отдаётся крупными порциями, а не посимвольно: так шлёт сервер.
